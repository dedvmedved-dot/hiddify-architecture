## Status Taxonomy

### PASS
- **Meaning:** Check completed successfully, all criteria met
- **Formed by:** Validators (exit 0), pytest (all tests pass), CI steps (exit 0)
- **Used by:** All validators, CI workflows, evidence files, acceptance docs
- **Conflict potential:** PASS with BLOCKED deployment is NOT a conflict — validators PASS means evidence is structurally correct, BLOCKED means deployment not authorized

### FAIL
- **Meaning:** Check failed — criteria not met, error detected
- **Formed by:** Validators (exit 1), pytest (test failures), CI steps (non-zero exit)
- **Used by:** All validators, CI workflows, evidence files
- **Conflict potential:** FAIL on semantic metadata check does NOT mean deployment FAIL — it means evidence structure is incomplete

### BLOCKED
- **Meaning:** Operation prevented by safety gate or missing precondition
- **Formed by:** Safety gates (exit 1 with specific message), deployment-phase-summary
- **Used by:** Safety gates, deployment evidence, acceptance docs
- **Conflict potential:** BLOCKED deployment with PASS validators is NORMAL (gates are working correctly)

### SUCCESS
- **Meaning:** CI job completed (all steps passed)
- **Formed by:** GitHub Actions runner
- **Used by:** GitHub Actions UI, ci-summary.txt
- **Conflict potential:** SUCCESS CI with BLOCKED safety gate is possible with `continue-on-error: true`

### ERROR
- **Meaning:** Unexpected failure (not a validation failure)
- **Formed by:** GitHub Actions runner (job crash, timeout)
- **Used by:** GitHub Actions UI
- **Conflict potential:** None

### WARNING
- **Meaning:** Non-critical issue detected
- **Formed by:** Linters (yamllint, markdownlint)
- **Used by:** Lint outputs
- **Conflict potential:** WARNING does not block PASS

### PENDING
- **Meaning:** Awaiting external input or action
- **Formed by:** Acceptance docs, deployment records
- **Used by:** Stage acceptance.md, deployment-record.md
- **Conflict potential:** None — PENDING is a state, not a result

### SKIPPED
- **Meaning:** Step not executed (upstream failure or condition)
- **Formed by:** GitHub Actions runner
- **Used by:** CI job outputs
- **Conflict potential:** SKIPPED due to `continue-on-error: true` upstream failure

### N/A
- **Meaning:** Not applicable in current context
- **Formed by:** Evidence files, owner-input-checklist
- **Used by:** Evidence declarations
- **Conflict potential:** N/A should be replaced with explicit NO or UNKNOWN in evidence

## Status Transition Rules

```text
PENDING → BLOCKED (safety gate)
PENDING → PASS (validation passes)
BLOCKED → PENDING (owner input received)
FAIL → (requires fix, then re-run)
```
