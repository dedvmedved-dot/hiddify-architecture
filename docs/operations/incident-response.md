# Incident Response

**Status:** DRAFT

## Overview

This document describes incident response procedures.

## Severity Levels

| Level | Description | Response Time | Escalation |
|-------|-------------|---------------|------------|
| P1 — Critical | Complete outage | Immediate | Owner + ChatGPT |
| P2 — High | Degraded service | 1 hour | Owner |
| P3 — Medium | Minor impact | 4 hours | Hermes |
| P4 — Low | Cosmetic issue | Next business day | Hermes |

## Response Procedure

1. **Detect** — Identify the incident
2. **Assess** — Determine severity and scope
3. **Contain** — Prevent further damage
4. **Resolve** — Fix the issue
5. **Recover** — Restore normal operations
6. **Review** — Post-incident analysis

## Post-Incident Review

Every P1/P2 incident requires:
- Timeline of events
- Root cause analysis
- Corrective actions
- Preventive measures
